# Нейросетевой синтез четырёхплоскостного фазового ДОЭ

Совместный ResUNet принимает четыре целевых изображения 128×128 и генерирует **один фазовый ДОЭ**: PNG 128×128, 8 bit, Grayscale. Веса включены в репозиторий и Docker-образ. Для применения сети не нужны обучающий датасет, Google Drive или доступ в интернет.

## Быстрый запуск в Docker — CPU

Требуется установленный Docker. Все библиотеки автоматически устанавливаются при сборке.

```bash
git clone https://github.com/ZurabBregadze/informatika-doklad-nuclear-it-hack.git
cd informatika-doklad-nuclear-it-hack
docker build -t nuclear-doe:cpu .
mkdir -p output
docker run --rm --network none \
  -v "$PWD/examples/sets/sample_0451:/input:ro" \
  -v "$PWD/output:/output" \
  nuclear-doe:cpu
```

Результат: **`output/doe_phase.png`**. Для своих изображений замените путь до `sample_0451` на папку своего комплекта. В ней должны находиться `image_1.png` … `image_4.png` либо `1.png` … `4.png`.

Файлы не переупорядочиваются по содержимому:

| Номер входа | Расстояние от ДОЭ |
|---|---:|
| 1 | 24.1 мм |
| 2 | 25.3 мм |
| 3 | 26.5 мм |
| 4 | 27.7 мм |

Для произвольных имён задайте четыре пути явно, в этом порядке:

```bash
docker run --rm --network none \
  -v "/absolute/path/to/targets:/input:ro" \
  -v "$PWD/output:/output" \
  nuclear-doe:cpu \
  --inputs /input/a.png /input/b.png /input/c.png /input/d.png \
  --output /output/doe_phase.png --device cpu
```

## Несколько комплектов за один запуск

Модель загружается **один раз**, затем обрабатывает все комплекты. Подкаталоги сортируются по имени; четыре изображения внутри каждого подаются совместно. В примере ниже пять разных комплектов.

```bash
mkdir -p output
docker run --rm --network none \
  -v "$PWD/examples/sets:/input:ro" \
  -v "$PWD/output:/output" \
  nuclear-doe:cpu \
  --input-root /input --output-dir /output --device cpu \
  --report /output/run.json
```

Выход: `output/<имя_комплекта>/doe_phase.png` для каждого подкаталога. `run.json` содержит SHA весов, выбранную эпоху, устройство, время загрузки модели и времена обработки комплектов. Существующий выходной PNG перезаписывается атомарно. Перезапись входных изображений запрещена.

## Docker с NVIDIA GPU

Для Linux-хоста с NVIDIA GPU и уже работающей поддержкой `docker run --gpus all`:

```bash
docker build \
  --build-arg TORCH_INDEX_URL=https://download.pytorch.org/whl/cu126 \
  -t nuclear-doe:cuda .
docker run --rm --gpus all --network none \
  -v "$PWD/examples/sets:/input:ro" \
  -v "$PWD/output:/output" \
  nuclear-doe:cuda \
  --input-root /input --output-dir /output --device cuda \
  --report /output/run_gpu.json
```

CUDA-библиотеки PyTorch устанавливает Dockerfile из [официального индекса PyTorch](https://pytorch.org/get-started/previous-versions/#v2-14-1). CPU-вариант не требует GPU и остаётся основным переносимым запуском. `--device auto` выбирает CUDA при её доступности, иначе CPU. Apple MPS не используется.

## Контракт входа и выхода

- Четыре статических непрозрачных изображения **128×128**. Размер не меняется автоматически.
- Для grayscale `L` используется исходная амплитуда `pixel/255`, как при обучении. RGB преобразуется в grayscale стандартным `Pillow.convert('L')`. Также поддерживаются непрозрачные palette/binary/alpha-изображения; прозрачные и 16-bit входы отклоняются с понятной ошибкой.
- Выход — **ровно один PNG ДОЭ на комплект**, размер 128×128, `uint8`, PNG color type 0, без alpha.
- Код фазы: `0 → −π`, `255 → +π`, округление к ближайшему целому. Декодирование: `φ = code × 2π/255 − π`.
- Длина волны 532 нм, шаг ДОЭ 10 мкм, равномерное единичное освещение. Френель использует естественный выходной шаг `dx_out = λz/(128 dx)`.

Нейросеть выдаёт конечную фазовую маску. В inference нет GS, оптимизации маски градиентным методом или классического синтеза после предсказания.

## Устройство метода

```text
Четыре цели одновременно
  → совместный ResUNet → четыре обучаемых комплексных поля
  → физическое обратное распространение Френеля
  → обучаемое пространственно-частотное объединение → фазовый выход
  → две обучаемые стадии обратной связи с физическим распространением
  → конечный фазовый ДОЭ
```

В каждой стадии поправку предсказывает нейросеть. Классической замены амплитуды, как в GS, нет. Fourier-ветви смешивают признаки обучаемыми фильтрами в частотной области, свёртки сохраняют локальную обработку. В стандартной конфигурации 2 995 501 параметр. Физические слои входят в сеть и функцию потерь.

Исходники нейросети: `src/doe_p0/model.py`; физика: `src/doe_p0/fresnel.py`; точка запуска: `infer.py` и `src/doe_p0/inference.py`. Docker копирует только модули нейросетевого inference и не включает GS/обучение.

## Обученные веса

`weights/model.pt` содержит готовые веса для inference; `weights/model.json` — конфигурацию, происхождение, эпоху и SHA-256. Это обычные файлы репозитория, не Git LFS-ссылки. На старте проверяется контрольная сумма. Веса включены в Docker-образ и не скачиваются при запуске.

Включены веса, обученные **с нуля на большом датасете** на кластере (Tesla V100-SXM2-16GB): та же архитектура `joint_spectral_v2` (width 32, 2 стадии обратной связи, 2 995 501 параметр), те же функция потерь и гиперпараметры (AdamW, lr 1e-4, batch 4, plateau-LR). Эпоха 53 — минимальный validation loss (validation PCC 0.563, SSIM 0.482). Исходный checkpoint имеет SHA-256 `da7d9f351525980292c86457ccbab11bf0a71a5d8fe1702eae5b1325991cbd87`; контрольная сумма компактного файла — в `weights/model.json`.

Данные: 1800 train / 230 validation комплектов, стратифицированная выборка из 5000 / 500 с сохранением долей 11 типов комплектов (плотные, смешанные и разреженные сцены × степень перекрытия; `reports/cluster_dataset/training_subset_info.json`). Источники изображений: фото (COCO, DIV2K и др.), текстуры, символы и одежда (MNIST, Omniglot, Fashion-MNIST), синтетика. Проверка автора: точных пиксельных совпадений между train/val/test нет (`dataset_audit.json`).

## Результаты на независимых тестах

Тесты не участвовали ни в обучении, ни в выборе эпохи: `main` — 800 комплектов того же распределения, плюс 8 отдельных наборов по типам сцен (всего 1980 комплектов, 7920 изображений). Маска и реконструкции проходят 8-bit PNG-квантование; реконструкция делится на свой максимум, цель — `pixel/255`. SSIM — глобальная формула со слайдов (`C1=0.01²`, `C2=0.03²`). Метрики усредняются по четырём плоскостям, затем по комплектам.

| Тест (комплектов) | Сеть, SSIM ↑ | Сеть, PCC ↑ | Численный метод GS-200 + Adam-300, SSIM | его PCC | Сеть / численный, SSIM |
|---|---:|---:|---:|---:|---:|
| main (800) | **0.483** | 0.562 | 0.525 | 0.611 | 92% |
| reference (50) | **0.765** | 0.818 | 0.794 | 0.840 | 96% |
| similar (150) | **0.590** | 0.654 | 0.600 | 0.676 | 98% |
| photo (300) | **0.473** | 0.513 | 0.519 | 0.560 | 91% |
| ood_photo (200) | **0.467** | 0.504 | 0.537 | 0.570 | 87% |
| texture (150) | **0.465** | 0.515 | 0.545 | 0.588 | 85% |
| sparse (150) | **0.442** | 0.565 | 0.495 | 0.627 | 89% |
| charts (30) | **0.413** | 0.537 | 0.484 | 0.648 | 85% |
| mixed (150) | **0.388** | 0.515 | 0.429 | 0.572 | 90% |
| **среднее по 9 тестам** | **0.498** | **0.576** | 0.548 | 0.632 | **91%** |

Численный метод — индивидуальная оптимизация маски для каждого комплекта (GS 200 итераций, затем Adam 300 шагов по той же метрике); его метрики посчитаны с делением цели на свой максимум. При таком же правиле у сети меняется только charts (SSIM 0.378) и в третьем знаке sparse/main; остальные значения совпадают.

Сравнение вариантов сети на тех же тестах (среднее по 9 тестам, SSIM / PCC):

| Вариант | SSIM | PCC |
|---|---:|---:|
| **Обучение с нуля на нашем датасете (эти веса)** | **0.498** | **0.576** |
| Дообучение весов малого эксперимента (400 комплектов, эпоха 63) на том же датасете, 35 эпох | 0.488 | 0.566 |
| Предыдущая архитектура CNN + U-Net, 5000 комплектов, 150 эпох | 0.401 | 0.509 |

Обучение с нуля лучше дообучения на всех 9 тестах (SSIM +0.008…+0.016).

## Время

Медиана, прогретые замеры, без загрузки модели и записи файлов (`reports/cluster_dataset/timing_v100_cpu.md`):

| Устройство | батч 1, мс/ДОЭ | батч 64, мс/ДОЭ |
|---|---:|---:|
| Tesla V100-SXM2-16GB (сеть → 8-bit фаза) | 21.4 (≈47 ДОЭ/с) | 8.0 (≈124 ДОЭ/с) |
| CPU кластера, 8 потоков | 294 | — |

Численный метод GS-200 + Adam-300 на той же V100 — 36–58 мс на комплект при пакетной обработке по 50 комплектов (`numeric_gs_adam_summary.md`) и требует оптимизации заново для каждого комплекта. Обучение: 53 эпохи × 153 с ≈ 2.25 ч на одной V100.

Полные таблицы (`compare_target255.md/.csv`), кривые обучения, столбцы по тестам и примеры реконструкций по плоскостям — в `reports/cluster_dataset/`. Результаты малого эксперимента (400 / 50 / 50, прежние веса) остаются в `reports/small_dataset/` и [отчёте](docs/RESULTS.md).

Смешение глубин остаётся ограничением: хуже всего сеть работает на `mixed` (сильно различающиеся сцены в четырёх плоскостях) и на мелких деталях (`texture`, `charts`).

## Проверка и воспроизводимость

Workflow `.github/workflows/docker-smoke.yml` собирает CPU-образ, запускает пять разных комплектов без сети и проверяет PNG-заголовки: 128×128, 8 bit, Grayscale. Это функциональная проверка, а не оценка качества.

Локальные тесты:

```bash
python -m pytest -q
```

Параметры обучения, разбиение данных, функция потерь и протокол сравнения с GS описаны в [документации по воспроизводимости](docs/TRAINING.md). Машиночитаемые отчёты и иллюстрации находятся в `reports/small_dataset/`. Датасет в репозиторий не включён; для повторения обучения необходимы данные в указанной структуре.
