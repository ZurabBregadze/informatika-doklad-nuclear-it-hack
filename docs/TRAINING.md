# Воспроизводимость обучения и сравнения

Документ описывает эксперимент `joint_spectral_v2`, ревизия обучения 2.1, которому соответствуют опубликованные веса и [результаты](RESULTS.md). Команды выполняются из корня репозитория. Для применения готовой модели обучение не требуется: запуск Docker описан в [README](../README.md).

## Данные и разбиение

Датасет `doe_targets_500_safe` содержит 500 комплектов по четыре амплитудных PNG 128×128: 400 train, 50 validation, 50 test. Используется исходное фиксированное разбиение; комплекты между частями не перемешиваются. Изображения происходят из MNIST, FashionMNIST и Omniglot. Данные в репозиторий не включены.

Ожидаемая структура:

```text
data/doe_targets_500_safe/
  train/<sample>/image_1.png ... image_4.png
  val/<sample>/image_1.png ... image_4.png
  test/<sample>/image_1.png ... image_4.png
  manifest.csv
```

Каждое изображение — статический непрозрачный PNG режима L, 128×128, с ненулевой амплитудой. Порядок плоскостей фиксирован: 24.1, 25.3, 26.5, 27.7 мм. Входные значения равны `pixel/255`; они интерпретируются как амплитуда, а не интенсивность.

Перед обучением `audit_dataset` проверяет структуру, формат и отсутствие одинаковых пиксельных изображений между частями. При наличии манифеста с колонкой `file` дополнительно проверяются его соответствие PNG, плоскости, расстояния, записанные SHA и повторения доступных идентификаторов источников/групп. Это не исключает недокументированное семантическое сходство. Результат сохраняется в `dataset_audit.json`.

Fingerprint использованного датасета: `747961ccf8c44d76f6a243aa08c68306f91030ba56ca7dcd2b8bed8cafa08b9d`. При сравнении fingerprint сверяется с checkpoint. Test не используется для градиентного обучения или автоматического выбора checkpoint, но этот test уже изучался при разработке архитектуры и не является новой независимой финальной проверкой.

## Архитектура и физика

Совместный ResUNet принимает `[B,4,128,128]` и предсказывает четыре комплексных поля. Каждое поле обратным оператором Френеля переносится на сетку ДОЭ. Обучаемое объединение формирует единичный фазор; затем выполняются две обучаемые стадии обратной связи с общими весами. На каждой стадии сеть получает цели и текущие распространённые поля, формирует комплексные сообщения и поправку фазы.

В bottleneck объединения и поправки фазы используются Fourier-ветви: проекция в 16 каналов, rFFT, обучаемое смешивание низких частот, IFFT и обратная проекция. Сохраняются по 8 вертикальных частот с обоих концов спектра и 8 горизонтальных частот; начальный масштаб residual-ветви — 0.01. Ширина сети 32, нормировка GroupNorm, активация SiLU; всего 2 995 501 обучаемый параметр.

Все поправки предсказываются нейросетью. При inference нет GS, замены амплитуды целевой или оптимизации отдельной фазовой маски. Физические слои — прямое и обратное распространение Френеля.

Single-FFT Fresnel использует длину волны 532 нм, шаг ДОЭ 10 мкм, размер 128×128 и равномерное единичное освещение. Выходной шаг каждой плоскости `dx_out = λz/(128 dx)` зависит от расстояния; цели трактуются на этих естественных сетках. Внутри сети применяется унитарная нормировка распространения; квадратичные фазовые множители сохраняются. Исходники: `src/doe_p0/model.py`, `src/doe_p0/fresnel.py`.

## Функция потерь

Для конечной маски loss усредняется по четырём плоскостям и батчу:

```text
L_final = mean[(1 − PCC) + (1 − SSIM_global) + 0.1 × amplitude_MSE]
L_train = L_final + 0.2 × mean(L_intermediate)
```

PCC и SSIM вычисляются для амплитуд, нормированных по собственному максимуму. SSIM — глобальная формула с population-дисперсиями, `C1=0.01²`, `C2=0.03²`, range=1. Для amplitude MSE целевая амплитуда нормируется до RMS=1 и сравнивается с амплитудой унитарного распространения. PCC-слагаемое выключено для пространственно постоянной цели, поскольку Pearson там не определён.

Вспомогательный loss применяется к начальному выходу и первой коррекции. Validation loss относится только к конечной маске, без вспомогательной добавки. Градиенты проходят через дифференцируемое распространение и непрерывную фазу; PNG-квантование не входит в обучающий loss. Validation PCC/SSIM измеряются отдельно после PNG-эквивалентного квантования. Реализация — `src/doe_p0/losses.py`.

## Параметры и запуск обучения

| Параметр | Значение |
|---|---:|
| Архитектура / ширина / стадии обратной связи | joint_spectral_v2 / 32 / 2 |
| Оптимизатор | AdamW |
| Learning rate / weight decay | 1e-4 / 1e-4 |
| Batch size / clipping нормы градиентов | 4 / 5 |
| Seed Python, NumPy, PyTorch | 0 |
| Максимум эпох / patience / min_delta | 200 / 10 / 1e-5 |
| ReduceLROnPlateau: factor / patience / min_lr | 0.5 / 2 / 1e-6 |
| Вспомогательный вес | 0.2 |
| Тип вычислений сети | float32 / complex64 |

Scheduler отслеживает validation loss с абсолютным порогом `min_delta` и снижает LR после трёх эпох без значимого улучшения. Ранняя остановка срабатывает после десяти последовательных эпох без уменьшения loss более чем на `1e-5` относительно последнего значимого лучшего уровня. Ухудшение также увеличивает счётчик; снижение LR его не сбрасывает.

```bash
python -m pip install -r requirements.txt
python train.py
```

`train.py` задаёт `DATA_ROOT`, `OUTPUT`, `CONFIG` и `RESUME`; по умолчанию используются показанная структура данных и `runs/joint_spectral_v2_1`. `device=auto` выбирает CUDA при доступности, иначе CPU; MPS не используется. В опубликованном эксперименте применялась T4 и два CPU-потока, что записано в `weights/model.json`; исходный `train.py` задаёт четыре потока. Для совпадения конфигурации требуется `threads=2`. Seeds фиксируются, TF32 и cuDNN benchmark отключены; детерминированные алгоритмы включены в режиме предупреждений. Побитовая идентичность между разными устройствами и версиями библиотек не гарантируется.

| Файл | Содержимое / критерий |

| best_ssim.pt | Максимальный средний validation SSIM после квантования |

| history.csv / history.json | Loss и компоненты, validation-метрики, LR, нормы градиентов |
| stage_history.csv / diagnostics.json | Промежуточные выходы на фиксированных validation-сценах |
| learning_curves.png / validation_examples.png | Кривые обучения и примеры |
| config.json / dataset_audit.json / status.json | Конфигурация, проверка данных и состояние запуска |

В опубликованном эксперименте основной критерий — минимальный validation loss: выбран `best.pt` эпохи 63, совпадающий по тензорам с `best_ssim.pt`. Обучение остановилось на эпохе 73. Для продолжения того же запуска `RESUME` указывает на `OUTPUT/'last.pt'`; inference-веса не содержат состояния оптимизатора. Архитектура, данные и настройки восстанавливаются из checkpoint. Завершённый по исходному критерию запуск дополнительных эпох не выполняет.

`weights/model.pt` — компактный экспорт выбранной модели без AdamW/RNG; `weights/model.json` содержит конфигурацию, эпоху и SHA исходного checkpoint и экспортированного файла. Численные значения и происхождение весов приведены в [отчёте](RESULTS.md).

## Протокол сравнения с GS

```bash
python compare.py
```

`compare.py` использует тот же датасет и `runs/joint_spectral_v2_1/best.pt`, оценивает все 50 test-комплектов (`LIMIT=None`). Baseline — параллельный четырёхплоскостный GS с равными весами плоскостей, 200 итераций, seed=0, CPU/float64. Нейросеть работает на выбранном устройстве в float32. GS применяется только как отдельный baseline, вне нейросетевого inference.

Для обоих методов одинаково:

1. Фаза кодируется и сохраняется как PNG 8 bit: `0 → −π`, `255 → +π`, округление к ближайшему целому.
2. Сохранённая маска читается и декодируется; четыре поля восстанавливаются через Fresnel в float64.
3. Амплитуда `|U|` каждой реконструкции нормируется по собственному максимуму и сохраняется в PNG 8 bit.
4. После чтения реконструкции из PNG вычисляются Pearson и глобальный SSIM; цель также нормируется по собственному максимуму.
5. Метрики усредняются по четырём плоскостям, затем по комплектам. Константная картинка даёт неопределённый Pearson (`null`); такие значения не исключаются из среднего скрытно.

Validation использует эквивалентное квантование в памяти; соответствие PNG-протоколу проверено тестами. Это оценка амплитуды, а не интенсивности `|U|²`. Глобальный SSIM отличается от локального SSIM со скользящим окном; значения нельзя напрямую сопоставлять с другим определением метрики.

В `results/joint_spectral_v2_1/` сохраняются `metrics.csv`, `summary.json`, `protocol.json`, `metrics_comparison.png`, `timings.json`; для каждой сцены — `comparison.png`, фазовые маски, цели, реконструкции, карты ошибок и метрики обоих методов. `protocol.json` фиксирует SHA checkpoint, fingerprint, порядок сцен, настройки GS и устройство. Повторный запуск с тем же протоколом использует завершённые сцены; другой протокол требует нового каталога результата.

## Измерение времени

Качество и время измеряются раздельно. Benchmark использует первые три test-сцены, три повтора, прогрев и синхронизацию CUDA. Дополнительно сеть измеряется на CPU рядом с GS. Сохраняются исходные замеры, медиана, p10/p90, версии библиотек, dtype, устройство и число потоков.

- `core`: цели уже на устройстве → непрерывная фазовая маска. Для GS включены создание операторов и инициализация.
- `pipeline`: CPU-цели → синтез → перенос фазы на CPU → квантование/декодирование → четыре реконструкции float64 на CPU → uint8-массивы.

Чтение PNG, загрузка весов, кодирование/запись файлов, метрики и графики исключены из benchmark. Время обучения измеряется отдельно. Вычисление истории ошибки GS отключено (`record_history=False`), что не меняет фазовую маску. Малое число повторов ограничивает оценку хвостовых задержек; GPU-сеть против CPU GS — сравнение разных вариантов запуска. Отдельный официальный inference CLI `infer.py --report` фиксирует загрузку модели и обработку комплектов; это другой протокол времени.

Тесты проверяют прямой интеграл Френеля, энергию, inverse/adjoint, комплексные градиенты, GS, PNG/метрики, backward сети, Fourier-ветви, раннюю остановку и путь train → checkpoint → resume → сравнение на искусственной выборке.
