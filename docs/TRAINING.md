# Обучение и воспроизводимость текущего решения

Документ описывает архитектуру опубликованных весов эпохи 53 и доступные способы повторного запуска. Метаданные — [weights/model.json](../weights/model.json), результаты и границы их проверки — [RESULTS.md](RESULTS.md). Готовая модель запускается без обучения по [README](../README.md).

## Данные

Текущая модель обучена с нуля на 1800 train / 230 validation комплектах, отобранных из 5000 / 500 со стратификацией по типам сцен. Основной test содержит 800 комплектов, восемь дополнительных тестовых наборов — ещё 1180. Полные данные не включены. [Сведения о выборке](../reports/cluster_dataset/training_subset_info.json) содержат seed=0 и количества по типам; они не содержат списка выбранных идентификаторов и полного кода формирования подвыборки.

Для обучения и встроенного сравнения требуется заранее подготовленный каталог `data/main_subset/`:

```text
data/main_subset/
  train/<sample>/image_1.png ... image_4.png
  val/<sample>/image_1.png ... image_4.png
  test/<sample>/image_1.png ... image_4.png
  manifest.csv
```

Название каталога — локальное соглашение; фактический путь задаётся `DATA_ROOT` в `train.py` и `compare.py`. Для сравнения опубликованных весов нужен именно подготовленный набор с fingerprint `b2d6b47e3a0609344d08ab87c399d031ccdf5fc3f63ed2d44bc8febff1950895`. Другой набор не воспроизводит исходный эксперимент; `compare.py` проверяет fingerprint. Одних количеств по типам недостаточно для побитового восстановления подвыборки.

Каждый вход — статический непрозрачный ненулевой PNG режима L, 128×128; четыре изображения подаются совместно. Значения `pixel/255` трактуются как амплитуды. Порядок `image_1..4` соответствует 24.1 / 25.3 / 26.5 / 27.7 мм. `audit_dataset` проверяет формат, структуру и точные пиксельные совпадения между частями. При наличии манифеста с колонкой `file` проверяются записанные SHA, плоскости, расстояния и доступные идентификаторы источников/групп. Семантическое сходство этим полностью не исключается.

## Архитектура и физика

Совместный ResUNet принимает `[B,4,128,128]` и выдаёт четыре комплексных поля. Обратное распространение Френеля переносит их на сетку ДОЭ; обучаемое пространственно-частотное объединение формирует единичный фазор. Две стадии нейросетевой обратной связи с общими весами используют цели и текущие распространённые поля для предсказания комплексных сообщений и поправки фазы.

Ширина 32, GroupNorm, SiLU, 2 995 501 параметр. В bottleneck объединения и поправки фазы Fourier-ветвь проецирует признаки в 16 каналов, смешивает низкие частоты обучаемыми фильтрами и возвращает их через IFFT. Используются по 8 вертикальных частот с обоих концов спектра и 8 горизонтальных частот rFFT; начальный residual-масштаб 0.01.

Single-FFT Fresnel: длина волны 532 нм, шаг ДОЭ 10 мкм, размер 128×128, равномерное единичное освещение, естественный выходной шаг `dx_out = λz/(128 dx)`. В сети применяется унитарная нормировка. Квадратичные фазовые множители сохраняются.

Поправки фазы предсказывают обучаемые слои. При inference нет GS, классической замены амплитуды, Adam или оптимизации каждой маски. Код совместимости с более ранними checkpoint сохранён в общих модулях и не выбирается текущей конфигурацией; опубликованные веса используют `joint_spectral_v2`.

## Функция потерь

```text
L_final = mean[(1 − PCC) + (1 − SSIM_global) + 0.1 × amplitude_MSE]
L_train = L_final + 0.2 × mean(L_intermediate)
```

Усреднение идёт по батчу и четырём плоскостям. Для PCC и глобального SSIM амплитуды и цели нормируются по собственному максимуму; C1=0.01², C2=0.03², population-дисперсии, range=1. PCC-слагаемое выключено для пространственно постоянной цели. Для amplitude MSE цель имеет RMS=1 и сравнивается с амплитудой унитарного распространения. Вспомогательный loss применяется к начальному выходу и первой коррекции.

Validation loss относится только к конечной маске. Градиенты проходят через непрерывную фазу и физику; PNG-квантование не входит в обучающий loss. Validation PCC/SSIM отдельно вычисляются после PNG-эквивалентного квантования с нормировкой цели по максимуму. Предоставленная внешняя тестовая CSV использует у сети цель `pixel/255`: это иной протокол, его значения не следует напрямую отождествлять с validation.

## Конфигурация и запуск

| Параметр | Значение из метаданных |
|---|---:|
| Architecture / width / feedback_steps | joint_spectral_v2 / 32 / 2 |
| AdamW: learning rate / weight decay | 1e-4 / 1e-4 |
| Batch size / clipping нормы градиентов | 4 / 5 |
| Seed / CPU-потоков | 0 / 8 |
| max_epochs / patience / min_delta | 100 / 10 / 1e-5 |
| Plateau scheduler: factor / patience / min_lr | 0.5 / 2 / 1e-6 |
| Auxiliary weight | 0.2 |
| Вычисления сети | float32 / complex64 |

```bash
python -m pip install -r requirements.txt
python train.py
```

`train.py` использует эти параметры и создаёт новый запуск в `runs/current_model/`. `RESUME=None` означает обучение с нуля; для продолжения того же запуска используется `OUTPUT/'last.pt'`. Веса inference не содержат optimizer/RNG и не подходят для resume. `device=auto` выбирает CUDA при доступности, иначе CPU; MPS не используется. Обучение опубликованных весов выполнено на Tesla V100-SXM2-16GB. Seeds фиксируются; TF32 и cuDNN benchmark отключены, детерминированные алгоритмы включены в режиме предупреждений. Побитовое совпадение разных устройств и версий библиотек не гарантируется.

В репозиторном коде scheduler снижает LR после трёх эпох без значимого уменьшения validation loss; ранняя остановка срабатывает после десяти таких эпох, максимум — 100. Ухудшение увеличивает счётчик, снижение LR его не обнуляет. `best.pt` выбирается по фактическому минимальному loss независимо от порога min_delta.

Предоставленная история опубликованного запуска содержит 53 эпохи. На последней `bad_epochs=0`, минимум loss — эпоха 53, максимум SSIM — эпоха 52. Причина завершения исходного запуска не установлена; повторный запуск скрипта не обязан завершиться на эпохе 53. Утверждение, что исходное обучение остановилось по plateau или что ранняя остановка была отключена, этими файлами не подтверждается.

Опубликованная модель выбрана по validation loss. Компактный экспорт — `weights/model.pt`, идентификация — `weights/model.json`. Test не является критерием автоматического выбора эпохи.

```bash
python export_weights.py runs/current_model/best.pt
```

Эта команда заменяет опубликованные inference-веса и метаданные результатом нового обучения. Она не требуется для применения включённых весов. Метрики отчёта относятся только к указанному в нём SHA; новый экспорт требует отдельной оценки.

## Встроенное сравнение с обычным GS

```bash
python compare.py
```

По умолчанию используются `weights/model.pt`, `data/main_subset/`, все test-сцены (`LIMIT=None`), GS-200, seed=0, вывод в `results/current_model_gs200/`. Baseline работает на CPU в float64, сеть — на выбранном устройстве в float32. Численный GS не входит в нейросетевой inference.

Оба метода сохраняют фазовый PNG 8 bit (`0 → −π`, `255 → +π`), затем декодируют его и восстанавливают четыре амплитуды Френеля в float64. Каждая амплитуда нормируется по своему максимуму и сохраняется в 8-bit PNG. После чтения вычисляются Pearson и global SSIM; цель здесь также делится на свой максимум. Метрики усредняются по четырём плоскостям и комплектам. Неопределённый Pearson константного изображения записывается как `null` и не исключается скрытно.

Сохраняются PNG, карты ошибок, `comparison.png`, `metrics.csv`, `summary.json`, `protocol.json` и `timings.json`. Протокол фиксирует SHA, fingerprint, порядок сцен и настройки. Изменение протокола требует нового каталога результатов.

Этот скрипт не воспроизводит внешнюю CSV из отчёта: в ней baseline GS + Adam и другое правило нормировки цели у сети. Реализации внешнего GS + Adam и исходных данных девяти наборов в репозитории нет. По новой оценке обычным GS нельзя перезаписывать или переименовывать опубликованные результаты GS + Adam.

## Время и проверки

Benchmark `compare.py` измеряет отдельно `core` (цели на устройстве → непрерывная фаза) и `pipeline` (CPU-цели → фаза → 8-bit квантование → четыре реконструкции float64 → uint8-массивы). По умолчанию: три test-сцены, три повтора, прогрев, синхронизация CUDA; загрузка модели, чтение/запись PNG, метрики и графики исключены. У GS отключена запись истории ошибки без изменения маски. Эти режимы отличаются от внешней сводки V100, где pipeline заканчивается получением 8-bit фазы.

```bash
python -m pip install -e '.[test]'
python -m pytest -q
```

Тесты проверяют Френель, энергию, inverse/adjoint, комплексные градиенты, GS, PNG/метрики, backward сети, checkpoint/resume и раннюю остановку на искусственных данных. Workflow Docker собирает CPU-образ, обрабатывает пять встроенных комплектов без сети и проверяет PNG-контракт. Встроенные комплекты служат функциональными примерами, а не новым test для отчёта.

`predict.py` использует текущие веса и встроенный комплект для экспорта маски и реконструкций; `gs.py` запускает обычный GS на тех же примерах. Для сдачи и обработки пользовательских изображений основной интерфейс — `infer.py`, описанный в README.
