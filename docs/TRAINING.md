## Запуск из PyCharm

1. Откройте эту папку как проект. Выберите Python с установленным PyTorch. На этом компьютере проверен `/opt/anaconda3/bin/python`. При выборе другого интерпретатора установите в него `requirements.txt` через настройки Python Interpreter или командой `python -m pip install -r requirements.txt` в соответствующем окружении.
2. Откройте `train.py` и нажмите Run. Пути вычисляются от файла, рабочая директория PyCharm может быть любой. В локальной исследовательской копии входной датасет находится в `data/doe_targets_500_safe`; после клонирования GitHub его нужно предоставить отдельно.

4. Для своих четырёх PNG настройте `INPUT`, `CHECKPOINT` и `OUTPUT` в `predict.py` и запустите его.

Короткие тесты используют искусственные данные и несколько шагов оптимизатора. На Mac `device='auto'` выбирает CPU, на компьютере с CUDA — GPU. MPS для комплексной FFT не используется. Веса v2 появятся после вашего запуска; рост качества относительно v1 пока не установлен.

## Модель

Четыре изображения одновременно → совместный ResUNet → четыре комплексных поля → четыре точных обратных оператора Френеля → пространственно-частотное обучаемое объединение полей на сетке ДОЭ → единичный фазор.

В v1 один энкодер отдельно обрабатывал каждую пару «цель, глубина». В v2 вход — четыре канала целей `[B,4,128,128]`; выход — восемь каналов, по амплитуде и фазе для каждой плоскости. Порядок каналов задаёт четыре фиксированных расстояния. С самого начала каждое предсказанное поле может зависеть от всех целей.

В bottleneck сети объединения и сети поправки фазы добавлена Fourier-ветвь: проекция в 16 каналов → FFT → обучаемое смешивание каналов на низких частотах → IFFT → проекция обратно. Используется по 8 вертикальных частот с обоих концов спектра и 8 горизонтальных частот rFFT. Ветвь добавляется к свёрточным признакам с начальным масштабом 0.01; исходные признаки и высокочастотные детали сохраняются в residual/skip-путях. Это адаптация общего пространственно-частотного принципа, не точное воспроизведение SFO-solver: https://pmc.ncbi.nlm.nih.gov/articles/PMC12368012/ .

По умолчанию выполняются ещё две стадии нейросетевой обратной связи с общими весами. На каждой стадии модель распространяет текущий фазор на четыре плоскости, обрабатывает цели и текущие поля нейросетью, переносит обученные комплексные сообщения обратно на сетку ДОЭ и предсказывает поправку фазы. Весь каскад обучается end-to-end. Для эксперимента с одним проходом укажите `feedback_steps=0` в новом запуске. Итераций GS внутри нейросети нет.

`width=32`, GroupNorm и SiLU. Последний выход модели — комплексный фазор единичного модуля. PNG формируется из его аргумента. Это собственная архитектура на основе обсуждённой идеи комплексных полей и физических слоёв.

В стандартной конфигурации v2 **2 995 501 обучаемый параметр**; у v1 было 717 831. Одновременно изменены совместный энкодер, ширина и частотные ветви: следующий запуск проверяет их совокупный эффект, а не вклад каждого изменения отдельно.

Все поправки маски предсказывает сеть. В inference нет замены амплитуды по правилу GS, запуска численного оптимизатора или GS после нейросети. Френель выполняет физическое распространение. Наличие обучаемых повторных стадий нужно описывать организаторам именно как часть нейросети; окончательную трактовку правил определяют организаторы.

Архитектура записывается в `config.json` и checkpoint. Старые checkpoint без поля `architecture` автоматически загружаются как v1 и сохраняют прежний граф вычислений. Веса v1 нельзя использовать как resume v2: новые формы слоёв требуют нового обучения. Старые файлы из Downloads не изменяются.

## Данные и разбиение

`doe_targets_500_safe.zip` содержит 500 четвёрок и 2000 PNG. Используется готовое разбиение `train=400`, `val=50`, `test=50`. Четвёрки не перемешиваются между split. В начале обучения проверяются размеры, формат, четыре плоскости, SHA PNG из манифеста, повторения пикселей и записанных источников/групп между split. Итог сохраняется в `dataset_audit.json` внутри запуска.

Проверка не доказывает отсутствие всех возможных семантических сходств. Исходный манифест и отчёт генератора сохранены рядом с данными.

`image_1.png` → 24.1 мм, `image_2.png` → 25.3 мм, `image_3.png` → 26.5 мм, `image_4.png` → 27.7 мм. PNG читаются как амплитуды, сеть получает сырые уровни `/255`. Обе стороны loss и метрик дополнительно нормируются по собственному максимуму.

Для большего датасета смените `DATA_ROOT` в `train.py` и `compare.py`, затем укажите новую `OUTPUT`. Требуется такая же структура `train|val|test/<sample>/image_1.png ... image_4.png`. Новый датасет обучается с нуля. `RESUME` предназначен для продолжения того же запуска на тех же данных.

## Обучение и остановка

Настройки находятся наверху `train.py`. AdamW с начальным learning rate `1e-4`, weight decay `1e-4`, batch size 4 и clipping градиентов 5. В обновлении обучения 2.1 включён `ReduceLROnPlateau`: `factor=0.5`, `patience=2`, `threshold_mode=abs`, `threshold=min_delta`, `min_lr=1e-6`. Это означает снижение после трёх эпох без значимого улучшения validation loss. LR меняется для следующей эпохи; в историю записываются `learning_rate` и `next_learning_rate`.

Физический loss конечной маски равен среднему по четырём плоскостям:

`(1 − PCC) + (1 − SSIM_global) + 0.1 × amplitude_MSE`.

Для amplitude MSE целевая амплитуда нормируется до RMS=1, а распространение делится на известный модуль коэффициента Френеля, то есть используется унитарная нормировка. Энергия и квадратичные фазовые множители сохраняются. В train дополнительно добавляется `0.2 × средний loss промежуточных масок`. `train_loss` включает эту добавку, `val_loss` относится только к конечной маске.

**Остановка после 10 последовательных эпох без значимого уменьшения `val_loss` либо после 200 эпох.** Улучшение считается значимым, если оно превышает `min_delta=1e-5`. Небольшие улучшения суммируются относительно последнего значимого лучшего уровня. Ухудшение тоже увеличивает счётчик. Правило действует с первой эпохи. Снижение LR не сбрасывает счётчик ранней остановки; при непрерывном ухудшении обучение закончится после десяти эпох. Scheduler, AdamW, RNG и история восстанавливаются из `last.pt`. При resume checkpoint старой версии без scheduler сохраняется прежняя политика постоянного LR.

`best.pt` сохраняется по минимальному фактическому `val_loss`, независимо от порога min_delta. Test в обучении и выборе checkpoint не участвует. PCC и SSIM по каждой плоскости и в среднем сохраняются отдельно, criterion остановки — именно validation loss.

В `runs/joint_spectral_v2_1` будут:

- `best.pt` — минимальный validation loss; это основной checkpoint для `compare.py`.
- `best_pcc.pt` — максимальный средний validation PCC после 8-bit квантования.
- `best_ssim.pt` — максимальный средний validation SSIM после 8-bit квантования.
- `last.pt` — состояние в конце последней полностью законченной эпохи.
- `history.csv`, `history.json` — основной/вспомогательный/суммарный train loss, компоненты train/val loss, validation PCC/SSIM по плоскостям, использованный и следующий LR, средняя/максимальная норма градиента до clipping и доля батчей с clipping.
- `stage_history.csv` — PCC/SSIM каждой стадии и плоскости для первых четырёх фиксированных validation-сцен по всем эпохам.
- `diagnostics.json`, `validation_examples.png` — метрики и просмотр этих же validation-сцен на последней эпохе; stage 0 — начальный выход, stage 1/2 — обучаемые коррекции.
- `learning_curves.png` — обновляемые после каждой эпохи графики loss, компонентов, PCC, SSIM, LR и норм градиентов.
- `config.json`, `dataset_audit.json`, `status.json` — параметры и состояние запуска.

Дополнительные `best_pcc.pt` и `best_ssim.pt` содержат модель, конфигурацию, эпоху, validation-метрики и fingerprint данных; optimizer/RNG в них не дублируются. Для продолжения нужен `last.pt`. Основное правило выбора итоговой модели остаётся минимальный validation loss; дополнительный критерий выбирают по validation до просмотра test. При обновлении старого запуска дополнительные best-метрики отслеживаются с первой новой эпохи (`metric_selection_start_epoch`), поскольку веса всех прошлых эпох восстановить нельзя.

Для продолжения поставьте `RESUME = OUTPUT/'last.pt'` и снова запустите `train.py`. Восстанавливаются модель, AdamW, RNG и порядок выборки на границе эпохи. Сохраняются настройки исходного запуска. Повторный resume уже завершённого запуска дополнительных эпох не запускает.

Ctrl+C просит завершить текущую эпоху, выполнить validation и сохранить состояние. Принудительная кнопка Stop/Kill в PyCharm может оборвать процесс немедленно. Тогда продолжение пойдёт с последней законченной эпохи. Для независимого эксперимента задайте новую `OUTPUT` и оставьте `RESUME=None`.

## Сравнение PNG и метрик

`compare.py` сравнивает сеть и базовый GS с фиксированными `GS_ITERATIONS=200`, `GS_SEED=0` на одних и тех же test-сценах. Для предварительного просмотра поставьте `LIMIT=5`, а также смените `OUTPUT`, например на `results/preview`. Итоговое сравнение выполняется с `LIMIT=None`. Выбор лимита/seed/числа итераций GS фиксируется до просмотра test.

В `results/joint_spectral_v2_1` сохраняются:

- `metrics.csv` — PCC (КК) и SSIM (ИСС) для каждого метода, примера и плоскости.
- `summary.json` — средние метрики всего теста и каждой плоскости.
- `metrics_comparison.png` — средние PCC/SSIM по тестовым сценам.
- `<sample>/comparison.png` — строки четырёх плоскостей, колонки target, сеть, GS и две карты ошибок. На реконструкциях подписаны PCC и SSIM.
- `<sample>/neural/` и `<sample>/gs/` — `doe_phase.png`, четыре reconstruction PNG, четыре target PNG, карты ошибок и `metrics.json`.
- `protocol.json` — fingerprint данных, SHA/эпоха/критерий выбора checkpoint, настройки GS и устройства.
- `timings.json` — отдельный benchmark синтеза маски и получения четырёх квантованных реконструкций в памяти.

Оценка следует одному пути для обоих методов. Сначала сохраняется фазовая маска 8 bit, затем она читается, декодируется и распространяется через Френель. Амплитуды нормируются и сохраняются как reconstruction PNG. Метрики рассчитываются после повторного чтения этих PNG. Validation использует эквивалентные операции квантования в памяти, равенство проверено тестом.

КК — Pearson. ИСС — глобальный SSIM с population-дисперсиями, `C1=0.01²`, `C2=0.03²`, range=1. Константная картинка делает Pearson неопределённым, в JSON записывается `null`. Скрытого исключения таких плоскостей из среднего нет. Интенсивность `|U|²` вместо амплитуды `|U|` не используется.

Сравнение можно повторно запустить после прерывания, завершённые сцены читаются из результата. При изменении checkpoint/данных/настроек нужен новый `OUTPUT`. Скрипт проверяет совпадение данных с обучающим запуском.

GS работает на CPU в float64, сеть — на выбранном устройстве в float32. Качество оценивается прежним PNG-протоколом. Для скорости после оценки качества выполняется отдельный benchmark: первые три выбранные test-сцены, по три повтора. Прогрев исключён (две пары вызовов для сети и одна для GS); CUDA синхронизируется до и после измерения. Сеть дополнительно измеряется на CPU рядом с GS. Указаны устройство, dtype, версия PyTorch, число CPU-потоков, исходные замеры, медиана и p10/p90. Малое число повторов не даёт точной оценки хвостовых задержек.

`core` — цели уже на устройстве метода → непрерывная фазовая маска; для GS включены создание операторов и инициализация. `pipeline` — CPU-цели → синтез → перенос фазы на CPU → её 8-bit квантование/декодирование → четыре реконструкции Френеля float64 на CPU → uint8-массивы. Чтение датасета, загрузка весов, PNG-кодирование/запись, метрики и графики исключены. Первая холодная загрузка не измеряется. Время обучения — отдельная величина, в отношение задержек inference не включается.

Для сравнения/benchmark GS отключено вычисление ошибки после каждой итерации (`record_history=False`); фазовая маска побитово совпадает с обычным GS. CLI `gs.py` по умолчанию сохраняет полную историю как раньше. Отношение CPU GS к CUDA-сети характеризует конкретные варианты запуска; оно не является сравнением на одинаковом оборудовании. Даже CPU-сравнение использует разные указанные dtype. `TIMING_SAMPLES=0` в `compare.py` отключает benchmark.

Текущий test уже использовался при анализе v1. Он позволяет описательно сравнить v1 и v2 на тех же сценах; для окончательного независимого подтверждения после выбора архитектуры нужна новая отложенная выборка.

## Физика и базовый GS

Сохранён проверенный `src/doe_p0/fresnel.py`. Single-FFT Френель использует длину волны 532 нм, шаг ДОЭ 10 мкм, равномерное единичное освещение. Выходной шаг каждой плоскости `dx_out=λz/(128 dx)` различается по z. Целевые пиксели трактуются на этих естественных сетках.

Для отдельного численного расчёта в PyCharm откройте `gs.py`, при необходимости измените INPUT и нажмите Run.

Кодирование фазы `0 → −π`, `255 → +π`. GS равновесно объединяет обратные поля четырёх плоскостей. Его отдельный CLI доступен после `python -m pip install -e .`:

```bash
doe-gs 1.png 2.png 3.png 4.png --iterations 200 --output results/gs_only
```

Для независимого обучения используйте новое RUN_NAME. Сохранение требует доступного и свободного Google Drive.

Резервирование включает optimizer/scheduler/RNG и работает через необязательный аргумент `backup_dir` у `train`. PyCharm и Colab используют одну версию архитектуры. Архитектура v2, физическая модель, формула loss, протокол PNG/метрик и критерий остановки сохранены. В версии 2.1 изменено управление LR и расширена диагностика. Модель стала шире и требует больше ресурсов. Аппаратная проверка CUDA/T4 выполняется smoke-ячейкой в Colab. AMP не включён.

После обучения последующие ячейки выполняют сравнение с GS и сохраняют ZIP с PNG, CSV и JSON на Drive. У GS 200 итераций и seed=0, оцениваются все 50 test-сцен.

Ресурсы и длительность сессии зависят от доступности Colab. Документация: https://research.google.com/colaboratory/faq.html .
